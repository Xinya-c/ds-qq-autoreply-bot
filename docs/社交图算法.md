# 社交图算法（social_map）

> 一句话：**先判断“每句话在回哪句”，再把链接起来的话拼成一段对话，最后从对话里算人和人的关系。**

代码：`memory.py` 的 `social_map()` / `_link_score()` / `tie_line()`。
入口：`qq_autoreply.py` 认人时调 `mem.person_brief(uid, scope, viewer=...)`，关系行由 `tie_line()` 生成。

---

## 一、为什么要这张图

机器人要回答“你还记得 XXX 吗”，得知道两件事：

1. **我认不认识他**（隐私分级要用：能不能说、能说多少）
2. **我跟他什么关系**（语气要用：客气还是随便、能不能损）

只靠“有没有共同群”太粗：一个 500 人大群里可能从没说过一句话。
只靠“@ 次数”也不准：@ 只是开场动作，喊完没人应等于没聊。

所以这张图记录的顺序是 **聊过 > 喊过 > 同群**。

---

## 二、三步

### 第一步：给每条消息找「父消息」（它在回哪条）

每条消息回看前 12 条（`LINK_LOOKBACK`）、最多早 240 秒（`LINK_MAX_GAP`），
算一个「在回它」的分数，取最高的那个当父。

这也是判断依据的全部来源：

| 信号 | 权重 | 为什么 |
| --- | --- | --- |
| @ 命中该人 | **+0.45** | 直接点名，最强 |
| @ 了别人 | −0.22 | 在叫别人，不是回你 |
| 字面相似（bigram Jaccard） | **×0.55** | 内容信号比结构信号可靠 |
| 换人（不是自己连发） | +0.18 | 你一句我一句才是对话 |
| 自己连发 | −0.28 | 多为补充说明，不是回答 |
| 上句在问、这句像答（需有点共同词） | +0.12 | 问答配对 |
| 两句都是问句 + 有共同词 | +0.15 | 追问 |
| 两句都是问句 + 没共同词 | −0.25 | 各开各的话题 |
| 短消息（≤6 字） | +0.10 | 三五个字基本是在接话 |
| 时间越近 | ×0.10 | 权重刻意压低（见下） |
| 长度断崖（相差 ≥75%） | −0.08 | 行为突变 → 换话题 |
| 情绪翻面（愉快↔低落/不耐烦） | −0.10 | 同上 |
| 标点爆发（`？？`/`!!`）且无共同词 | −0.08 | 同上 |

另有两条在候选生成阶段加的：

| 信号 | 值 | 说明 |
| --- | --- | --- |
| 同人连发（≤90 秒） | 保底 **0.42** | 自己那几句必须留在同一段，否则上下文丢一半 |
| 二人世界（最近 4 条只有这两人） | **+0.15** | 口语闲聊常常毫无共同词（“在吗/在/问你个事/说”），语义永远连不上 |

**为什么时间权重压到 0.10**：第一版是 0.30，加上“换人 +0.20”就有 0.475，
直接过了阈值——语义根本没参与决策，结果两段同时进行的对话被并成一段。

### 第二步：easy-first 解码（先定最稳的）

把所有候选按分数**从高到低**处理，而不是按时间顺序逐条归段。

> 旧版是按时间贪心：第 3 条判错，第 4 条看“上一条是谁”时已经被带偏，一错到底。
> 先定最稳的，再用它们约束模糊的，错误不会连锁。
> （算法来源：TOIS《Revisiting Conversation Discourse for Dialogue Disentanglement》的 easy-first decoding）

三条护栏：

| 情况 | 门槛 |
| --- | --- |
| 两边都已有来有回（≥2 个人开口过） | **0.70** |
| 一边已成段 | 0.38 |
| 都是散句 / 单人说链 | 0.32 |
| 两边成段但**是同一批人** | 0.38（按“加入”处理） |

“已成段”按**开口过的人数**算，不是消息条数——一个人连发三句只是“链”，
两个人各说一句才算一段对话。否则两人各连发两句时会被切成两段，然后互不让步。

最后一条护栏是为这种情况留的：同一对人间隔几十秒各说两句，先各自成链，
再互相不许并 → 一人一段。判定“同一批人”就放行。

### 第三步：结算关系和语气

每个连通块（≥2 条消息）算一段对话，对块内每个人两两建边：

```
threads  一段对话 +1（最强信号）
turns    += 这两人在这段里各自说了几句之和
at       @ 次数（单独记，喊了没人应也算“认识”，但不算“聊过”）
last     最后一次互动时间
prof/neg/polite   说话糙度（Pennebaker LIWC 的中文近似）
```

坑（已修）：**不能边处理边记边**。中途才加入的人拿不到他进来之前的轮次，
实测“甲 3 句 + 乙 2 句”只记了 2 句。现在统一在线程走完后结算。

## 三、语气为什么能当关系信号

依据 ACL 2012《Self-Disclosure and Relationship Strength》（1100 万条推文）：

| 信号 | 强关系 | 弱关系 |
| --- | --- | --- |
| 脏话 | 0.0615 | 0.0085（**差 7 倍**） |
| 正面情绪词 | 0.31 | 0.33（**弱关系更客气**） |

**客气是距离，骂人是亲近。** 但对主人说“谢谢您”反而怪，所以只在够了样本
（≥4 句）时才下结论，且只用来润色措辞，不参与“能不能说”的判定。

### 一个反直觉的坑：自曝 ≠ 熟

同一篇还发现：个人信息（住哪、生日、家里几口人）在**弱**关系里**更多**——
新认识的人靠自曝做自我介绍，熟人早知道了。

所以代码里**刻意不统计自曝量**。拿“他跟我讲了很多私事”当亲密度，会把刚加
好友的人排到最前面。测试里专门锁了一条：一堆个人信息但不骂人 → 既不判“糙”
也不判“客气”。

## 四、参数与调法

```python
LINK_LOOKBACK   = 12     # 回看几条（控制 O(n·k) 规模）
LINK_MAX_GAP    = 240    # 父消息最多早多久（秒）
LINK_FLOOR      = 0.20   # 进候选的门槛
LINK_MIN_SCORE  = 0.32   # 散句连线
LINK_JOIN_SCORE = 0.38   # 往已成段里加
LINK_MERGE_SCORE= 0.70   # 两段都成段时合并
LINK_CONT_BONUS = 0.20   # “我在接着自己那段聊”
LINK_SELF_SCORE = 0.42   # 同人连发保底
LINK_SELF_GAP   = 90     # 同人连发的窗口（秒）
LINK_DUO_BONUS  = 0.15   # 只有我们俩在说
```

| 症状 | 调什么 |
| --- | --- |
| 一段对话被切成好几段（句数偏低） | 降 `LINK_MIN_SCORE`（0.32→0.28）或加 `LINK_DUO_BONUS` |
| 两段不相干的对话被粘成一段（跨组关系异常高） | 升 `LINK_MERGE_SCORE`（0.70→0.80） |
| 慢聊（间隔一两分钟）接不上 | 加 `LINK_MAX_GAP`（240→360） |
| 一句话被孤零零丢掉 | 加 `LINK_LOOKBACK`（12→16），代价是变慢 |

改完必须跑 `tools/e2e_smoke.py` 里的 `test_social_v2`（13 项），它锁的就是
“该分的分开、该合的合上、语气别乱下结论”。

## 五、局限（说清楚，别指望它解决一切）

1. **学术界做到顶也就 47%**（Ubuntu IRC 数据集：Elsner 线性 15.5、Kummerfeld
   feedforward 36.2、BERT+BiLSTM 46.8）。2025 年有微调 LLM + 图聚类做到 0.90
   的报告，但那是微调模型、且在同域数据上；我们用的是规则，别期望那个数。
2. **只看字面，不看语义**。`_jaccard` 是 bigram 重叠，同义改写（“饿了”vs“没吃饭”）
   连不上。要质变必须换本地向量（`embedder`），成本是每条消息一次前向。
3. **同一话题隔 4 分钟才有人接 → 会算成两段**。
4. **两个人同时在群里各说各的**，如果交替足够快，可能被并成一段。
   这是最容易出错的一类，也是 `LINK_MERGE_SCORE` 要设到 0.70 的原因。
5. **语气判定是词表匹配**，反讽、玩梗会错判（“谢谢您嘞”未必客气）。
   所以它只润色措辞，不参与隐私判定。

## 六、怎么自己看效果

```bash
# 最强的关系对（段数 / 句数 / @ / 脏话数）
python -c "
import sys; sys.path.insert(0,'.')
import qq_autoreply as qa
m = qa.AutoReply(qa.load_config()).mem; m.load_all()
seen, rows = set(), []
for a, ps in m.social_map().items():
    for b, d in ps.items():
        k = (min(a,b), max(a,b))
        if k in seen: continue
        seen.add(k)
        rows.append((len(d['threads']), d['turns'], d['at'], a, b))
for th, tu, at, a, b in sorted(rows, reverse=True)[:10]:
    print('%s ↔ %s  %d段 %d句 @%d' % (a, b, th, tu, at))
"
```

关系行（送进 prompt 的那句）：

```python
m.tie_line(主人QQ, 对方QQ)
# → 你跟他的关系：一起聊过 4 回，来回说了 77 句，说话挺糙的，不讲究，今天聊过
```

缓存：`_sm_key = len(_search.recs)`，记录数不变就直接用缓存（实测全量重算 0.01 秒，
2799 条归档）。
